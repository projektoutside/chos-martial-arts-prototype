# Two-Administrator Invite-Only Reset Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reset the live Cho application to exactly two fully privileged administrators, enforce administrator-created accounts, and show every invited user a database-backed welcome popup only after their first successful login.

**Architecture:** Keep the existing Supabase username-to-email adapter and active-staff-owner authorization contract. Expand it from one legacy owner to two owners, add self-scoped welcome RPCs, remove public registration, and perform the live reset through a guarded Node script that snapshots rows before mutation and never stores credentials. Deploy and verify the safe authorization path before deleting any identity.

**Tech Stack:** React 19, TypeScript, Vitest/Testing Library, Supabase Postgres/Auth/Edge Functions, Node.js, Vite, Capacitor Android, Cloudflare Pages.

## Global Constraints

- Target only Supabase project `zfuwbbepsnmmlpgfkmhz`.
- Final live state: exactly `Dev123` and `Manager1`, both active staff owners with full access.
- Passwords are transient secrets: never commit, print, report, or bundle them.
- Create and verify a private pre-reset snapshot before deletion.
- Never export password hashes, access/refresh tokens, API keys, sessions, or secrets.
- Disable self-signup in both the UI and Supabase Auth configuration.
- Do not use user-editable Auth metadata for authorization.
- Keep the future spotlight tutorial out of this task.
